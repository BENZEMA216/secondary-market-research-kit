# 场景路由策略：三层说明与研究路线

版本：0.3.0  
日期：2026-09-04  
状态：本地研究实现，不是盈利证明，也不是实盘系统

## 先说结论

这套策略不是把三个信号硬叠在一起，而是先判断市场处于哪一种信息场景，再运行对应的交易规则：

- 没有观察到关联文章时，研究“超跌后的反转”。
- 出现明确、可核验的正向财报或指引时，研究“事件后的延续”。
- 信息覆盖不完整、事实冲突或时间点不可信时，直接不交易。

三层的权限必须分开：

~~~text
点时事件与文章数据
        ↓
事件层：盘前确定 event / reversal / abstain
        ↓
交易层：只运行被选中场景的量价触发
        ↓
AI 层：仅在选定实验中，对已合格的指引上调候选做二次否决
        ↓
确定性组合风控 → 模拟撮合 → 持仓与退出
~~~

AI 可以提前读取材料，但它在逻辑上没有资格跳过事件层和交易层。最终买卖、仓位、止损、熔断和恢复都由确定性代码控制。

## 一、交易层（指标层）

### 这一层做什么

交易层把日线和分钟线转换成可执行候选，并统一处理入场时点、止损、退出、仓位与组合风险。它回答的是：

1. 价格是否真的出现了预先定义的形态？
2. 信号在当时是否已经可见，而不是用了未来数据？
3. 下一根 bar 是否仍有合法入场位置？
4. 这笔交易在组合限额内能买多少？

### A. 反转支线

第一步是日线三段 MACD 底背离：

- MACD 参数为 `12/26/9`。
- 只看直方图位于零轴下方的三段负波。
- 三个价格低点依次更低。
- 三个负柱极值依次抬高。
- 第三段负柱第一次收缩时，产生一个日线候选。
- 候选只在下一交易日有效；不是“未来若干天内都可使用”。

第二步是可选的五分钟四线随机指标确认：

- 四条平滑随机指标参数为 `(9,3)`、`(14,3)`、`(40,4)`、`(60,10)`。
- 四线都严格低于 `20` 时进入 armed 状态。
- 快线 `D9` 回到 `20` 上方后进入 bounced 状态。
- 价格随后二次测试前低。
- `D9` 或 `D14` 至少比第一次低点高 `2` 个指标点。
- 四条线同时比上一根上升，且 `D9 < 80`，才完成触发。
- armed 后最多等待 `12` 根五分钟 bar。

确认只能使用已经结束的 bar，入场价取下一根五分钟 bar 的开盘及同步报价。若盘中先触碰日线第三段低点、分钟数据断档、交易日不连续、证券身份变化或价格复权基准变化，候选失效。

反转退出规则：

- 初始止损：日线第三段负波的价格低点。
- 目标：入场到初始止损距离的 `2R`。
- 最长持有：30 个交易日。
- 同一根 bar 同时触及止损和止盈时，按止损优先。

### B. 事件延续支线中的价格确认

事件层先给出资格，交易层再检查市场是否真正响应：

- 当日开盘相对前收盘跳空至少 `10%`。
- 09:30、09:35、09:40、09:45 四根五分钟 bar 的总成交量，至少达到过去 20 个交易日平均全天成交量。
- 09:50–10:55 之间，某根已完成的五分钟 bar 最高价严格突破前 20 分钟开盘区间高点。
- 在下一根五分钟 bar 开盘及同步报价处入场。

事件支线退出规则：

- 初始止损：前 20 分钟开盘区间低点。
- 第 5 个持仓日收盘减半，并把余仓止损提高到入场价。
- 从第 5 日起，如果日收盘跌破 EMA10，则下一交易日开盘退出余仓。
- 最长持有 60 个交易日。

### C. 共享组合风控

当前冻结的是研究政策，不是经收益优化后的最优参数：

| 控制项 | 规则 |
|---|---|
| 股票池 | 美股普通股；前收盘 ≥ 5 美元；20 日中位成交额 ≥ 2,000 万美元 |
| 报价 | 入场时 NBBO spread ≤ 30 bp |
| 单笔计划风险 | 正常状态下，初始止损风险 ≤ 净值 0.25% |
| 最大仓位数 | 持仓加未成交订单合计最多 4 个 |
| 总初始止损风险 | ≤ 净值 1% |
| Gross exposure | ≤ 净值 1 倍 |
| 单票金额 | ≤ 净值 25% |
| 单行业金额 | ≤ 净值 35% |
| 单 cluster 风险 | 初始止损风险合计 ≤ 净值 0.5% |
| 回撤 5% | 新增单的单笔风险预算减半 |
| 回撤 10% | 锁存停止新增；保护性退出继续 |
| 当日亏损 1% | 当天停止新增 |
| 恢复 | 10% 锁存必须显式 reset；AI 无权操作 |

本地 `PaperBroker` 使用买入 ask、卖出 bid，再叠加显式滑点与佣金；只模拟全成或拒绝，不模拟真实排队、冲击、部分成交和停牌成交。

### 交易层接下来要研究什么

1. **先做独立基线。** 分别跑日线反转、日线加分钟确认、零文章过滤、持续文章 veto，以及事件价格形态，不能先看组合总收益。
2. **证明时序因果。** 所有指标只用完成 bar；所有成交只用下一 bar；交易日历、半日市、拆股和 ticker 变化必须点时处理。
3. **避免幸存者偏差。** 使用当时上市且后来可能退市的股票池，不用今天的赢家固定名单。
4. **让样本先够用。** 每个主要支线先争取至少 100 个上游场景，再讨论参数优劣；样本不足只报告覆盖问题。
5. **用真实执行成本。** 主成本假设、10/25/50 bp 敏感性、NBBO、最低佣金、停牌和 gap-through-stop 分开报告。
6. **做等风险、等暴露对照。** 原版、单个风险层、完整风险层必须在可比暴露下评估，避免把“少交易”误判为更好策略。
7. **做锁定 OOS。** 参数和数据处理先冻结，再进入未见区间；报告 CAGR、最大回撤、Calmar、尾部损失、恢复时间、平均暴露、换手、净 R，以及删除最大 5 笔后的结果。

## 二、事件层

### 这一层做什么

事件层不是预测价格，而是在开盘前回答三个问题：

1. 指定文章源在所需窗口内是否覆盖完整？
2. 是否存在与该证券关联、且当时已经可见的文章或公司事件？
3. 事件事实是否足以把候选归入明确的正向财报或指引实验？

事件层输出 `event`、`reversal` 或 `abstain`。这个选择在盘前信息截止时确定，不能等盘中价格走出来后再改写路线。

### 四类点时账本

| 账本 | 作用 |
|---|---|
| Coverage manifest | 证明某个数据源、证券和时间窗是否完整覆盖 |
| Article presence | 记录文章身份、证券关联、类别、实际可见时间和修订 |
| Structured events | 记录财报、指引、口径、期间、数值、验证状态和字段证据 |
| Reference snapshots | 保存事件发生前已经可见的市场预期或上一次同口径指引 |

所有账本都依赖稳定 `security_id`、append-only revision、实际可见时间和证据 hash。格式正确不等于内容真实；代码只能验证收到的数据是否自洽，不能证明供应商没有漏数据。平台 adapter 必须在进入校验器之前，把自身的数据源标识规范化为冻结配置里的通用值 `news_feed`；未规范化的标识会按 fail-closed 原则被拒绝。

### 事件窗口与路由

事件窗口严格定义为“前一正常交易日收盘之后、当日正常开盘之前”。

- 覆盖不完整：`COVERAGE_UNKNOWN`，不交易。
- 覆盖完整且零关联文章：允许进入反转研究支线。
- 存在文章但类别、证券关联或时间不可信：不交易。
- 存在确定性分类的财报或指引文章：进入事件研究支线，继续判断 E1/E2。
- 迟到文章、冲突修订、缺字段或不完整 reference：不交易，不能退回反转支线。

### 事件实验分层

- `E0`：只验证 gap、量能和开盘区间突破，不声称事件已确认。
- `E1`：存在确定性分类、点时可见的财报或指引文章。
- `E2A`：EPS 与收入都严格高于同期间、同口径的事前预期，且完整指引没有下调。
- `E2B`：同一财政年度、同一口径的全年指引中点至少一项上调，其余项不下调；不额外要求财报双 beat。

`E2A` 与 `E2B` 是两个独立实验，不能把条件混在一起后只汇报一个结果。

### 事件层接下来要研究什么

1. **覆盖率。** 按证券、日期、盘前窗口和数据版本验证文章全集，而不是看到一条记录就假设完整。
2. **点时可见性。** 区分发布时间、抓取时间、修订时间和回测可见时间；晚到的旧文章仍可能否决交易。
3. **证券关联与类别准确率。** 用人工标注集测 precision、recall、冲突率和 abstain 率；未知分类必须保持未知。
4. **参考值质量。** E2A 的 consensus、E2B 的前次同口径全年指引都必须是事件前快照；财年、GAAP/adjusted、单位和区间不可错配。
5. **修订处理。** 新修订不能污染历史已成交交易，也不能让旧的未成交候选继续存在。
6. **分层消融。** 依次比较 E0→E1→E2A/E2B 的新增信息价值，并报告每一层过滤掉多少候选、为什么过滤。
7. **独立复核。** 至少对关键样本用第二条数据链核对时间、事件类型与原始材料，不能只比较两个转售接口的同源结果。

## 三、AI 层

### 这一层做什么

AI 层只负责把非结构化公司材料变成“待代码核验的候选事实”，并对选定事件做二次复核。当前真实实现聚焦公司级、全年收入与 EPS 指引，不负责通用新闻理解。

输入合同要求：

- 恰好两份材料：当前材料与此前同口径材料。
- 明确的证券身份、ticker、财政年度与研究 lane。
- 文件路径、文件 hash、发布时间和捕获时间。
- 只允许从给定材料中抽取，不允许用模型记忆补缺。

工作流：

~~~text
归档材料与 hash
  → 第一次独立抽取
  → 第二次从原材料重新抽取，不读取第一次答案
  → 代码校验 JSON 字段、Decimal、单位、财年、source_id、精确引文和数字 token
  → 两次规范化事实完全一致
  → 代码计算指引中点及上调/持平/下调
  → 写入 SQLite revision
~~~

状态机为：

~~~text
RUNNING → CHECKED_CANDIDATE / ABSTAIN / CONFLICT / INCOMPLETE / BLOCKED
~~~

迟到且已经被新修订取代的请求标为 `SUPERSEDED`。默认模型 provider 关闭；provider 不可用、输出不完整、schema 不符、引文或数字对不上、两次读取不一致时，都不能沿用旧结论。

### AI 的权限上限

当前 AI 工作流只可对已经通过事件层和价格层的 `E2B` 候选增加二次否决：

- 只能把候选保留或否决，不能创造一个合格事件。
- 不能自动写成 verified 事件事实。
- 不能决定买卖方向、入场价、仓位、止损或退出。
- 不能修改风险参数、解除回撤锁存或访问券商账户。
- 修订或失败时，可以取消尚未成交的旧候选；已经成交的历史不能被抹掉，保护性退出继续运行。

数据 schema 中允许存在外部已经合格的 `agent_extracted` 事件事实，但这属于另一条严格隔离的研究 lane。当前内置 AI 工作流没有实现“自动晋升为事件事实”，不能把两者混写成一个能力。

### AI 层接下来要研究什么

1. **建立人工金标准。** 覆盖错财年、口径变化、区间与单点、没有全年指引、单位变化、撤回指引、冲突修订和表格跨页。
2. **分别测单抽取与双抽取。** 报告字段准确率、误放行、漏放行、abstain、冲突、修订失败、延迟和成本；一致率不能代替真实性。
3. **防止历史知识泄漏。** 历史回放中只给当时可见材料，并承认模型可能记得历史；最终资格必须靠前向捕获证明。
4. **做无 AI 对照。** 在相同候选、成本、风险和时间窗下比较无 AI、单次抽取、双次抽取加复核，判断 AI 是减少错误还是只减少交易。
5. **测失败恢复。** provider 关闭、超时、截断、未知事件、修订并发和迟到响应都要 fail closed，且不能阻断已经持有仓位的保护性退出。
6. **记录运行身份。** 保存开始/完成时间、call ID、输入与输出 hash、可取得的 backend/version；拿不到精确模型版本时写 unavailable，不能猜。
7. **前向 shadow。** 在不下单的实时材料流上观察至少一个完整样本阶段，先验证事件准确率和工作流稳定性，再讨论收益贡献。

## 四、三层怎样一起验收

应先独立验证，再组合，推荐矩阵如下：

| 组别 | 主要问题 |
|---|---|
| M0 | 日线三段背离本身是否有信息量 |
| M1 | 五分钟四线确认是否增加价值 |
| M2 | 盘前零文章过滤是否增加价值 |
| M3/M4 | 分钟确认与持续文章 veto 是否增加价值 |
| E0 | 纯量价事件形态是否存在 |
| E1 | 确认“有事件”是否增加价值 |
| E2A | 双 beat 定义是否增加价值 |
| E2B | 全年指引上调定义是否增加价值 |
| E2B + AI | AI 二次否决是否降低误判且保留足够样本 |
| Router | 两条互斥支线合并后，是否优于等风险、等暴露的独立支线 |

组合结果至少同时报告：收益、最大回撤、Calmar、尾部损失、恢复时间、换手、平均与峰值暴露、成本、候选数、成交数、拒绝原因，以及删除最大 5 笔后的稳健性。

## 五、当前做到与没有做到

已经做到：

- 三层参考代码、冻结配置、组合风控、本地 paper 账本、修订和失败关闭已实现。
- 规则按完成 bar 和下一 bar 执行，关键身份、时间、价格基准和账本关系有自动测试。
- AI 工作流具备双读取、数值与引文校验、SQLite revision 和默认 provider-off。
- 公开 API、常量、配置、错误信息和测试统一使用描述性领域命名。

尚未做到：

- 没有完整的 QuantConnect 或其他平台三层 adapter；现有 M0 诊断不等于完整策略。
- 没有点时全美股、退市证券、完整新闻/reference、真实 NBBO、部分成交、停牌与冲击成本的正式数据链。
- 没有完整策略的 OOS、正式成本、等暴露对照或盈利证明。
- AI 没有实现全市场扫描、通用事件自动晋升、E2A 自动化、自动复盘 Agent 或实盘动作。

因此，这一版本可以交给回测接入者继续实现和证伪，但不能据此配置真实资金。
